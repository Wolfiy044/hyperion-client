Privacy

Last updated: October 12, 2026

1. Scope and contact

Hyperion Client is a Windows application for managing Minecraft: Java Edition profiles, modpacks and optional online social features. The developer's published contact is Wolfiy044, wolfiy388@gmail.com. Minecraft and third-party servers are separate services.

2. Authentication and local data

Microsoft sign-in uses the official Microsoft authentication flow. Hyperion does not request or store Microsoft account passwords. It processes authentication tokens, Minecraft usernames, UUIDs, entitlement and profile information to authenticate users and launch Minecraft. The Microsoft token cache is protected with Windows user-bound encryption. Local profiles, settings, installed content metadata, download caches and game logs are stored on the device. Logging out removes the launcher's cached authentication session; it does not delete profiles or online social history. Authenticated social and protected-session requests send a Minecraft access token to Hyperion's API, which validates the profile with Minecraft services. This token is used for verification and is not written to the backend's account records.

3. Online social features

When enabled and accepted, Hyperion's backend processes account identifiers, profile/status text, privacy preferences, friend requests and relationships, blocks, chat messages, groups, communities, parties, invitations, shared modpack information, events, reports and appeals. Presence can include Minecraft version, loader, profile and server address, subject to the user's privacy settings. Messages and shared information are disclosed to their intended recipients; community content is available to community participants. Authorized moderators can access reported content and moderation records. Privacy controls allow invisible status, hiding the server address, blocking users and limiting requests. Online requests also expose the network IP address to the receiving service.

4. Optional protected server sessions

Hyperion Anti-cheat runs only for a selected server session where protection is enabled or required, after the consent prompt. It uses a separate native user-mode process and requests Windows administrator permission. It checks the selected profile's mods, resource packs, shader packs, options and JVM arguments, and the Minecraft process for loaded modules, memory/thread integrity and attempts to modify or inject into that process. It does not capture screenshots or keystrokes. Relevant process/handle and Windows event information is used locally for these game integrity checks. Results, finding codes and flagged names, session and server identifiers, Minecraft account identity and connection information are sent to Hyperion's backend; protected servers receive the session admission status and violation codes. The current implementation can delete resource or shader packs in the selected profile that it identifies as x-ray packs. Declining consent or administrator permission prevents the protected start. Ordinary unprotected starts do not activate these checks. No custom kernel driver or persistent Windows service is installed.

5. External services and purposes

Hyperion communicates with its API at hyperion-api.metropolia-rp.com, Microsoft/Xbox/Minecraft services, Modrinth, CurseForge through its proxy, and applicable content hosts such as GitHub. Information is used to provide authentication, downloads, social communication, moderation and protected-session validation. Each external provider has its own privacy policy. The launcher has no advertising or payment checkout functionality. The developer does not sell personal information.

6. Storage and retention

Local settings, profiles, caches and logs remain until cleared or removed from the device. Social profile data, relationships, reports and moderation records are stored by Hyperion's backend and do not have a general automatic age limit. Direct chat history is filtered to 30 days and capped at 300 messages per conversation; community history is filtered to 14 days and capped at 300 messages. Removal occurs when the relevant data is accessed or updated, rather than through a guaranteed immediate deletion schedule. Group history and moderation/security records use record-count limits. Presence and invitations use temporary state. Protected sessions expire after 12 hours and are pruned on backend access/startup; security alert history is stored separately. Contact the developer to request access, correction or deletion of backend data. Uninstalling the launcher alone does not delete that backend data. Third-party providers determine their own retention periods.

7. Security and choices

HTTPS is used for remote API communication. Protected-session reports and launcher/guard communication are authenticated, and session secrets are not placed in command lines. Users can sign out, change social privacy settings, disable optional protection or use unprotected profiles. Required-protection servers may refuse access without a valid protected session. No system can guarantee absolute security.
